# 反馈候选与集中审议规范

本规范负责组织学习的“进料口”：让执行中的高信号问题先进入本机意见箱，再由用户触发集中审议。它不是看板、统计系统、第二套项目台账，也不自动修改 Skill。

## 1. 捕获什么

至少命中一类信号才投递候选：

- 用户明确纠正 Agent 对范围、权威、流程、分支、验证或发布的理解。
- 因现有规则、默认流程或职责边界不合理，造成回退、返工、冲突或显著浪费。
- Agent 发现 Skill 与真实项目冲突，或只能通过临时绕行完成。
- 同类问题再次出现，暗示上一次修复没有改到生产源。
- 用户显式要求“记录反馈”、“放入意见箱”或同等动作。

普通 Bug、单次命令拼写错误、项目特有业务事实、尚未验证的猜测和日常工作进度不默认投递。

## 2. 两条捕获路径

### Hook 兜底

`UserPromptSubmit` 只用本地、确定性规则识别明确纠正或投递请求。命中后只写入候选文件，向 Harness 返回空对象，不给当前 Agent 注入候选 ID、收集说明或处置指令；当前请求仍按原始用户语义处理。普通 prompt 不写入、不注入、不调用模型。

### Agent 后台提交

Agent 自己发现高信号治理缺口时，可从已加载 Skill 路径向上定位插件根，在后台静默运行：

```bash
node <plugin-root>/hooks/feedback-cli.js submit --summary "<summary>" --project-root "<project-root>" --evidence "<evidence-reference>" --quiet
```

`--quiet` 不输出候选 ID 或回执。正常面向用户的答复不显示内部标记、ID 或收集说明；CLI 不可用时跳过该次后台收集，不回退到可见标记。用户显式要求记录、查询或处理反馈时，才可返回最小必要的确认或结果。

## 3. 本机意见箱

默认路径是 `~/.senmu-buildos/feedback/`，可用 `SENMU_BUILDOS_DATA_DIR` 改到另一个本机数据根。它不在项目目录创建 README、台账或治理结构，不上传网络，不修改 Git。

每条候选为独立 JSON 文件，以稳定指纹防止同一事件重复写入。只保存：

- 候选 ID、时间、来源 Harness 和信号类型。
- 本机项目根、session ID 和可用的 transcript 引用。
- 经长度限制和常见密钥模式脱敏的短摘要。

文件和目录在支持 POSIX 权限的系统上分别使用 `0600` 和 `0700`。脱敏只是降低风险，不是完整 DLP；不应在反馈摘要中写密钥或客户数据。

## 4. 集中审议

用户要求“处理／整理 BuildOS 意见箱”时：

1. 从已加载 Skill 定位插件根，运行 `node <plugin-root>/hooks/feedback-cli.js pending --json`。
2. 按根因、适用范围和专业 owner 查重聚类，不按表面措辞或数量直接晋级。
   若现行 Skill 已覆盖该决策，同时检查实际 Harness、项目入口、脚本、validator 和行为测试是否消费它；“规则已写但行为仍错”默认是执行源缺口，不是再写一遍规则的证据。
3. 对每组只提出一个分类建议：`discard`、`project`、`buildos_candidate` 或 `needs_evidence`，并说明理由。
4. 先与用户确认分类和抽象；未授权时不修改项目、BuildOS、安装实例或发布状态。
5. 确认后用 `feedback-cli.js decide` 写入独立决策回执；原候选保留，不靠删除改写历史。

最小命令：

```bash
node <plugin-root>/hooks/feedback-cli.js pending --json
node <plugin-root>/hooks/feedback-cli.js decide --id <FB-id> --disposition <value> --note "<reason>"
```

## 5. 晋级后的边界

- `discard`：一次性、噪声、已有规则且只是未遵守，或无法形成可判定动作。
- `project`：回到项目自己的需求、架构、实现、流程或交付 owner；意见箱不复制正文。
- `needs_evidence`：记录需要哪个复现、验证或第二项目样本，不当长期规则执行。
- `buildos_candidate`：作为 BuildOS 源码项目的独立输入，再按整仓影响分析、测试和发布授权实施。

可选定时任务只可读取待处理候选并生成审议建议；不得无人审议地修改或发布 BuildOS。
