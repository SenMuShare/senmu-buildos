# 界面文案与内容设计规范

本规范负责跨页面长期生效的按钮、标签、状态、错误、提示、空状态和 AI 生成界面内容。它不替代项目已有设计系统、术语表或品牌语气，也不把单条翻译和普通文案修改升级为产品治理。

## 1. 规则层级

按以下顺序裁决：已确认产品行为与业务事实 > 项目术语、品牌语气和设计系统 > 目标平台惯例 > 本规范默认值。平台的大小写、按钮顺序或常见称呼可以不同，但不能削弱真实性、动作结果、风险说明和恢复方式。

没有项目内容 owner 时，把长期术语、对象名称和品牌语气写入现有产品规格书或设计系统；不要为 BuildOS 另建必须同步的文案台账。一次性活动文案、营销标题和项目专有业务术语留在项目。

## 2. 通用原则

- **说用户正在做的事。** 使用用户熟悉的对象、动作和结果。
- **先给重要结果。** 主文案先回答发生了什么、影响什么、下一步能做什么；原因、限制和技术详情按需后置。
- **同一事物只用一个名字。** 入口动作、页面标题、对象名称、状态和反馈保持一致；不要在“项目／任务／作业”之间无规则切换。
- **短但完整。** 删除寒暄、重复事实和无用修饰，不删除范围、后果、恢复条件或用户真正需要的限制。
- **语气与事实一致。** 普通状态只说明实际结果，不增加与结果无关的祝贺、感叹或拟人化情绪，也不承诺系统无法保证的结果。品牌语气只能在清晰和真实之后发挥作用。
- **不只依赖视觉。** 关键动作和状态不能只靠颜色、位置或图标表达；无文字图标需要可访问名称或必要提示。

## 3. 动作与按钮

按钮优先使用能够独立说明结果的动词或“动词＋对象”，例如“保存设置”“提交审核”“删除项目”。不要写“点击这里”，也不要用标题或说明句代替动作。

通用导航词只在流程已经明确、动作可逆且不会隐藏重要后果时使用：

| 文案角色 | 使用边界 |
| --- | --- |
| 下一步 / Next | 进入已经定义的下一步骤，本次点击不完成最终业务动作 |
| 继续 / Continue | 延续或恢复当前流程，去向从上下文可以明确判断 |
| 完成 / Done | 最后一步已经结束，不再要求后续提交或确认 |
| 返回 / Back | 回到上一层或上一步，不暗示保存、取消或提交 |
| 取消 / Cancel | 退出尚未生效的当前动作；是否保留草稿由产品事实决定 |
| 确定 / OK | 只用于确认已知信息或无法增加结果信息的通用确认；有具体业务结果时改写为该动作 |
| 好的 / Got it | 只表示已读，不执行保存、删除、提交或发布等业务动作 |

危险或不可逆操作必须写出真实动作和对象，确认说明写清主要后果；主按钮不能只写“确定”。按钮、标签、标题、菜单项和短表头通常不加句末标点。

## 4. 状态、错误与反馈

- **成功：** 结果已经在界面中明显可见时不重复弹窗；需要反馈时说明已完成的动作和受影响对象。
- **处理中：** 说明用户目标正在处理，不展示模型名、队列名、内部阶段或无法证明的百分比。任务可离开页面、可取消或耗时较长时，说明真实边界。
- **错误：** 使用“无法完成某动作”这类客观结果；原因已知时用用户能处理的语言说明，再给恢复动作。只写“操作失败”“参数无效”或内部错误码不算完整错误消息。
- **空状态：** 说明为什么当前没有内容，并只在存在合理下一步时提供主动作；不要用长篇功能介绍填满空白。
- **确认：** 只在动作有重要后果、容易误触或无法轻易恢复时打断用户。说明对象、后果和继续方式，不为普通可撤销动作增加确认层。

面向用户的主要消息不得包含数据库字段、枚举值、堆栈、Prompt、模型路由、流水线步骤或实现理由。排障确需保留时，放入可展开的“技术详情”或可复制诊断区域，并避免泄露敏感信息。

## 5. 生成式界面内容的附加约束

模型可以起草界面内容，但输出仍必须服从产品事实和前述规则。另行拒绝以下可观察问题：

- “好的，我来为你……”等模型自述、对话寒暄或工作过程汇报；
- 把需求原话、验收说明或内部讨论改写后直接展示给终端用户；
- 把尚未发生、无法确认或只在内部计划中的结果写成已经完成、一定成功或始终可用；
- 用大段解释掩盖一个本可明确命名的动作或错误。

交付前按对象名称、动作结果、状态事实、错误恢复和内部信息隔离五类统一检查，不按页面临时发明另一套说法。

## 6. 语种、平台与专项治理

中文界面读取[界面文案中文规范](界面文案中文规范.md)，英文界面读取[界面文案英文规范](界面文案英文规范.md)；多语产品分别读取目标 Profile，不把一种语言的语序、大小写或字数限制复制给另一种语言。翻译按意图和动作结果本地化，不逐词对应，也不拼接句子碎片。

移动端、Web 和企业后台遵循各自成熟交互惯例；发生表面冲突时，优先保留用户对动作、后果和恢复的理解。组件库默认文案只是可用默认值，不自动成为项目产品标准。

治理已有项目时，先从实际界面和项目 owner 盘点对象、动作、状态、错误和引导五类不一致，再回写唯一术语／产品 owner；不为专项治理长期增加审批流或第二份同步清单。
