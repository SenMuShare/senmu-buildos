# 交互动效与可访问性规范

本规范负责界面操作方式、状态反馈、动效、手势和可访问性。目标是让界面直接、可预测、可中断且在不同输入和能力条件下可用，不以“动得更多”或套用统一时间参数作为质量标准。

## 1. 先设计交互，再选择动效

每个关键交互先回答：用户要完成什么；触发方式是什么；立即反馈、处理中、成功、失败和取消如何表现；焦点和返回到哪里；能否撤销或恢复。产品行为不清时回到 Product，不用动画掩盖未定义状态。

增加动效前依次判断：

1. **频率**：键盘快捷操作、核心导航和高频重复动作优先即时切换或极轻反馈；罕见、解释性或完成时刻才有更大的表现预算。
2. **目的**：只接受反馈、状态变化、空间关系、减少突变、解释或低频愉悦；“看起来酷”不能单独成立。
3. **功能影响**：用户正在读、比较或操作的数据不为装饰持续移动；动效不得延迟输入、遮挡结果或阻断下一操作。
4. **替代路径**：减弱动效、键盘、触摸、精确指针和无悬停设备都必须完成同一任务。

没有合格目的时不增加动效，这是有效设计结论。

## 2. 运动的物理与时间关系

- 输入发生时立即给可感知反馈；拖动和滑动在交互过程中连续跟随，不只在结束后播放动画。
- 快速重复或可反向操作从当前屏幕状态继续，避免先完成旧动画再响应新输入。手势驱动场景优先能继承当前位置和速度的机制。
- 弹层从触发点建立空间关系；进入和退出使用可理解的对应路径。模态居中、面板从边缘进入等规则依真实空间关系决定，不机械统一。
- 预定且简单的变化优先现有组件能力或 CSS；需要程序控制时再评估浏览器动画接口；弹簧、拖拽、滚动编排或复杂时间线才评估现有 Motion／GSAP 等依赖。不得为淡入单独安装动画库。
- 优先变换与透明度等低成本属性，明确列出动画属性；避免无界 `transition: all`、持续触发布局和在父级更新继承变量驱动大量子元素。
- 时长、曲线、弹簧和交错先复用项目 Token，再按元素尺寸、距离、频率和产品气质调整。界面响应通常短于叙事动效；离场通常不应比进入更拖沓。没有运行观感证据时不把固定数字晋级为全局标准。

可中断性、浏览器负载和输入延迟必须用真实运行验证。源码中使用某个库或属性不自动证明动画流畅。

## 3. 手势与直接操控

- 保留用户抓取点，使用平台成熟事件模型和指针捕获，移动过程中一对一更新；多指、越界、取消和失焦必须有定义。
- 释放后的目标同时考虑位置、方向和速度；可拖拽边界用渐进阻力表达，不突然冻结。具体阈值由组件尺寸、平台惯例和真实设备测试决定。
- 动画期间不锁死无关输入；用户重新触发、反向拖动或退出时，从当前可见状态继续。
- 手势不能成为唯一入口。拖拽、滑动、长按和悬停功能同时提供可发现的按钮、键盘或菜单路径。

组件库已提供焦点、手势、碰撞、滚动锁和可访问语义时优先复用；自建必须证明现有能力不能满足已批准交互。

## 4. 可访问性是设计输入

按目标平台当前标准和项目规则验证，不用一张固定数字清单替代真实界面。至少覆盖：

- 语义结构、控件名称、可见标签和状态通知；
- 键盘顺序、可见焦点、跳过重复区域、弹层焦点进入与返回；
- 文本与关键图形对比、放大／缩放、动态字体和长文本重排；
- 触摸目标、相邻操作、防误触和危险操作恢复；
- 信息不只靠颜色、位置、图标、声音、振动或运动表达；
- 减弱动效时移除大幅位移、弹跳、视差和循环运动，保留有助理解的短淡化或状态变化；
- 透明材质在减少透明度、高对比和复杂背景下仍保持可读；
- 自动播放、闪烁、全屏运动和亮度突变有停止、替代或避免机制。

## 5. 设计与实现评审

评审先重现真实页面和关键状态，再记录位置、当前行为、用户影响和最小改进。优先级由任务失败、误操作、不可达、理解成本、频率和受影响用户决定，不以个人审美或“默认挑错”制造问题。

至少验证目标视口、键盘路径、触摸／指针、减弱动效、加载与失败、最长内容、快速重复触发和中途反向。动效需要在正常速度、慢放或逐帧下检查起止、曲线、原点和多个属性是否协调；手势应在真实设备验证。无法仅凭代码判断手感时明确标为待运行验证。
