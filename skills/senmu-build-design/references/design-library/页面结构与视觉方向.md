# 页面结构与视觉方向

选择方向时先看用户任务、内容密度、品牌资产和使用时长，不按行业标签机械套版。

| 方向 | 适合 | 结构骨架 | 主要风险 |
| --- | --- | --- | --- |
| 编辑叙事型 | 品牌故事、观点、案例、内容产品 | 强标题与主视觉建立主题，章节以留白、图文比例和滚动节奏推进 | 视觉节奏压过信息查找；正文可读宽度失控 |
| 产品证据型 | SaaS、工具发布、能力说明 | 价值主张后尽快出现真实产品或结果，再按问题、工作方式、证据和行动展开 | 堆卖点卡片；用装饰性假界面代替证据 |
| 工作台型 | 高频工具、编辑器、运营台 | 稳定导航、主工作区与按需检查器；把高频动作留在当前上下文 | 面板过多挤压主任务；移动端只做等比缩小 |
| 密集运营型 | 数据后台、队列、审核、批量处理 | 总览提供异常与下一步，列表／表格承担比较，详情按需展开 | 所有指标同权；大卡片降低扫描效率 |
| 沉浸展示型 | 作品集、空间体验、强视觉发布 | 以高质量素材为主轴，界面控制退后，章节或转场建立空间关系 | 素材不足仍强做沉浸；动效阻断阅读与操作 |

宏观结构只决定信息如何被看见，不决定产品必须增加哪些模块。目标内容与参考骨架不匹配时，优先调整骨架，不为填满版式制造功能或文案。
