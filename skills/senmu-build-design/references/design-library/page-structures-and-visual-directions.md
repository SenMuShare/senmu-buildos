# Page Structures and Visual Directions

Choose from user task, content density, brand assets, and session length rather than industry labels.

| Direction | Suitable for | Structural skeleton | Primary risk |
| --- | --- | --- | --- |
| Editorial narrative | brand stories, viewpoints, cases, content products | strong title/hero establishes theme; whitespace, image-text proportion, and scroll rhythm carry chapters | visual rhythm impedes information finding or reading measure becomes uncontrolled |
| Product evidence | SaaS, tool launches, capability explanation | show the real product/result soon after the value proposition, then problem, workflow, evidence, action | feature-card piles or decorative fake UI replacing evidence |
| Workbench | frequent tools, editors, operations | stable navigation, primary workspace, conditional inspector; frequent actions remain in context | panels crowd the task or mobile merely shrinks desktop |
| Dense operations | data administration, queues, review, batch work | overview surfaces exceptions/next actions; lists/tables compare; detail expands on demand | equal emphasis for every metric or oversized cards reducing scan efficiency |
| Immersive showcase | portfolios, spatial experiences, visual launches | high-quality assets lead; controls recede; sections/transitions establish space | forcing immersion without assets or letting motion block reading/action |

Macro structure determines how information is seen; it does not require new product modules. If content does not fit a skeleton, change the skeleton rather than manufacture features or copy.

## Composition and Narrative Choices

For a persuasive page with unresolved structure, sketch the focal relationship before detailed copy: an image with text in its quiet area, a centered object, the product/result as the stage, typographic composition, vertical stacking, a collage, or a justified split view. These are alternatives, not a required set. Existing brand/content constraints may eliminate most of them. Give the real product or result enough scale to be understood; an attractive generic illustration cannot substitute for capability evidence.

For workbenches and operations, put the task objects, exceptions and useful action within reach. Choose table, queue, canvas, detail or contextual inspector from the workflow; do not prescribe a row count, metric-card quota or decorative overview. Keep legitimate differences between a dense work surface and its marketing site.

Use scroll narrative only when progression explains a subject or serves an authorized showcase. Distinguish a one-time entrance from input-driven progress; the latter must work when reversing, jumping or loading midway. Storyboard the meaningful object/section transitions and reading pauses, not every decorative frame. Keep reading and primary actions available, with a reduced-motion/static path and a skip route when prolonged staging would impede the task. Ordinary pages need no scroll choreography or added library.

## Asset and Rendering Choices

Give each major asset a job: identify an object, explain a relationship, demonstrate a real result, or express a supported brand intent. Fix hierarchy before adding imagery. Choose the smallest medium that does the job:

- Reuse suitable project/brand assets first. Inspect the actual file and its source/use conditions; access to an image does not establish permission for publication. Keep provenance and any attribution with the project's existing asset records.
- Use photography, illustration or generated artwork when the subject/texture benefits. Define subject, viewpoint, light, background, text-safe space, crop and output use. Match a series through those relationships, not only a filter. Keep generated/synthetic images distinct from real product/customer evidence.
- Use editable layout, text, controls and data graphics for information and operation. Select interactive vector/canvas/3D when the object must respond to input, spatial change or viewpoint; a static illustration may be sufficient otherwise. Treat a rendered scene's fallback and input limitations as design constraints, not a reason to invent a second stack.
- Use pre-rendered video for a predetermined sequence. Check looping, seeking/reversal where needed, load and memory behavior; pre-rendered reflections or physics do not respond to arbitrary live content.

An image-generated UI concept is optional. Use it to explore composition, not to approve product states or replace working controls. Preserve existing brand and target languages, distinguish output pixels from logical viewport, and carry the selected relationships into normal project components. For a long concept, continue consistent sections only if one readable image cannot answer the question. Do not require a fixed prompt length, palette ratio, tiny type, provider or paid image step. Use authorized tools; missing capability can be handled with existing assets, a specification or an explicitly provisional mockup.

Judge assets inside the real composition at intended size. Check focus and narrow-screen crop, edge/alpha quality, legible overlaid text and coordinated lighting. For repeated sprites or states, retain identity, viewpoint, scale and a stable placement baseline. Compare alternatives using comparable source/asset quality. Keep originals and relevant generation/processing provenance in authorized project locations; publish only appropriately sized production assets. Do not report costs or performance improvements the tools did not measure.
