# 组件设计模式

组件模式用于承载任务，不按流行程度选择。先明确用户要比较、定位、编辑、推进还是查看结果，再选择最小组合。

| 模式 | 适用任务 | 必须成立的关系 | 避免 |
| --- | --- | --- | --- |
| 命令入口 | 快速定位动作、对象或导航 | 搜索、分组、键盘／触控路径、无结果和不可用状态清楚 | 把所有功能塞入命令面板，隐藏核心主路径 |
| 主画布＋检查器 | 编辑对象并调整属性 | 选择对象与检查器上下文同步；主画布保持视觉重心 | 永久展开所有配置；失去选择时仍显示旧属性 |
| 索引＋详情 | 从集合定位记录并查看上下文 | 选择、返回位置、深链和空／错状态稳定 | 点击后丢失筛选、滚动位置或选择反馈 |
| 比较矩阵 | 对多个方案、版本或指标做同维度比较 | 列与行语义固定，差异与口径可辨，窄屏有合理替代 | 用大量卡片迫使用户来回记忆 |
| 流程步进 | 有真实顺序、检查点或不可逆提交的任务 | 当前进度、已保存状态、返回影响和失败恢复明确 | 把可以直接完成的短表单强拆成多步 |
| 指标＋上下文 | 监控结果、趋势或异常 | 数值同时说明时间、口径、变化与下一步；异常可下钻 | 只展示孤立大数字或用颜色代替含义 |
| 预览＋提交 | 生成、发布、导入或批量修改 | 输入、预览、差异、确认、执行状态和失败恢复形成闭环 | 预览与实际执行采用不同数据或默认值 |

只设计任务真实存在的状态。常见状态可作为检查提示，但不为不存在的交互强造悬停、选择或批处理；关键状态必须能由实现和真实验证观察。
