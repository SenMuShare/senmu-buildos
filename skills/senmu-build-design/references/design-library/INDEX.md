# Design Library Index

This library contains task-selectable design experience, not project brand facts or frontend code. Apply the project's design owner and shared Design standards first; read one matching pack only when candidate patterns are needed.

| Current gap | Read | Outcome |
| --- | --- | --- |
| Overall direction, page narrative, or macro layout | [Page Structures and Visual Directions](page-structures-and-visual-directions.md) | suitable surfaces, structural skeleton, visual focus, common risks |
| Artwork, generated concepts, video/3D, or source suitability | [Asset and Rendering Choices](page-structures-and-visual-directions.md#asset-and-rendering-choices) | medium, source, implementation boundary and in-context evidence |
| Task-bearing interface pattern or complete state model | [Component Design Patterns](component-design-patterns.md) | task, component relationships, states, selection conditions |
| Playful loop, spatial control, or stateful animation | [Direct Manipulation and Play](component-design-patterns.md#direct-manipulation-and-play) | objects, visible state transitions, input and outcome verification |

Choose one primary direction, then draw only necessary component patterns from the other pack. Examples are candidates, not templates. Do not rotate themes for novelty, combine conflicting languages, or override an approved project system. Adjacent Design standards remain the owners of typography, color, tokens, motion, and accessibility.

These packs do not establish a vendor dependency, candidate quota, palette ratio or minimum animation count. Reuse the host/project capabilities and authorization already available; retain a useful substitute or an explicit limit when an optional capability is unavailable.
