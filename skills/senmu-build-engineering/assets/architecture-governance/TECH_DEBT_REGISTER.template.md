## 使用规则

- 只登记会持续增加维护成本或风险的已知问题，不把所有待办都包装成技术债。
- 临时补丁、长期忽略、兼容分支或 TODO 如代表真实债务，应引用债务 ID 或写清收口条件。
- 有意采用当前较小实现但存在已知容量、兼容或演进上限时，登记可观察的升级触发条件；代码内说明引用同一债务 ID，不另建平行注释账本。
- 修改债务所在模块时检查是否已满足偿还触发条件。
- 只有代码、测试、文档和旧入口都完成收口后，状态才能改为“已偿还”。
