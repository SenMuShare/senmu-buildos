## 2. 编码约定

- 遵守 PEP 8、PEP 257 和项目 `pyproject.toml`；项目配置决定行宽、目标版本和启用规则。
- 函数、方法和变量使用 `snake_case`，类和异常使用 `PascalCase`，常量使用 `UPPER_CASE`。
- 公共边界编写准确类型；限制 `Any`、`cast()`、`# type: ignore[...]` 和宽泛异常的范围。
- 禁止可变默认参数、裸 `except:`、普通业务代码的星号导入和无理由修改 `sys.path`。
- 分离业务计算和数据库、文件、网络等 I/O；让副作用和失败方式可发现。
- 结构固定的数据优先使用 `dataclass`、Pydantic 模型或明确类型，不让任意 `dict` 传遍系统。

## 3. 中文注释与 docstring

- 代码标识符使用英文；内部业务注释和 docstring 默认使用简体中文。
- 公共模块、类、函数和方法编写 docstring；私有且自解释的短函数不添加噪声文字。
- docstring 风格：`<Google / NumPy / Sphinx>`；章节内容使用中文。
- 重点说明业务契约、前置条件、返回语义、副作用、幂等性和异常，不重复类型标注。
- 为复杂业务、事务、并发、重试、兼容、安全和性能取舍解释原因。
- 修改实现时同步更新或删除注释，不保留被注释掉的旧代码。
