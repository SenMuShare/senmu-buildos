# 前端工程契约与验证规范

本规范用于项目缺少、冲突或正在改变前端工程契约时，校准浏览器／客户端实现。已有项目规则足以指导普通实现时直接遵守项目，不为“前端开发”重复加载通用教材。

## 1. 前端拥有的实现边界

前端负责把已批准的产品行为和设计规格实现为可观察界面：渲染与交互状态、浏览器路由、客户端数据获取边界、表单提交、组件公共契约、响应式实现、可访问性实现和浏览器验证。它不重新决定产品功能、文案语义或视觉方向。

先读取项目现有框架、路由、状态管理、请求层、组件系统、Token、测试与构建入口。优先延续已有公开扩展点；只有现有能力无法满足真实契约时才引入依赖或抽象。

## 2. 状态与数据边界

- 区分服务器事实、URL／导航状态、会话或持久状态、表单草稿和纯展示状态；同一事实只保留一个权威来源。
- 服务端数据由数据获取层拥有，组件接收明确结果与动作；不要把请求、缓存、表单和全局 store 复制成多份可写状态。
- 为真实路径处理加载、空、错误、重试、失效、并发提交和成功反馈。乐观更新必须有失败恢复与最终服务端校准。
- URL 能表达的筛选、分页、选择或深链按项目约定进入路由；刷新、后退和分享后不应无故丢失用户上下文。
- 表单同时明确客户端即时反馈与服务端最终校验；禁用按钮不能代替重复提交、权限或幂等保护。

## 3. 组件与页面结构

组件边界围绕稳定职责、复用需求和状态所有权建立，不按视觉切块数量机械拆分。公共组件暴露业务无关且可维护的输入、事件和状态；页面组合保留场景语义。一次性差异优先局部组合，不为未来假设增加通用配置层。

设计 Token、组件变体与无障碍语义优先来自项目 design owner。组件库提供实现能力，不自动定义项目视觉标准或产品文案。当前 API、性能或框架惯例需要专项知识时再调用对应平级 Skill，不把其手册复制进本规范。

## 4. 验证

按风险选择类型／静态检查、组件测试、路由与数据集成测试以及真实浏览器验证。至少覆盖本次改变的目标视口、关键状态、键盘／触控路径、控制台错误和必要网络行为；修复缺陷先复跑原始页面与操作路径。

快照或单一 DOM 断言只能证明其观察面。布局、换行、焦点、滚动、响应式、动效和浏览器 API 行为需要真实渲染或等价运行证据；未覆盖设备、浏览器或状态必须明确。
