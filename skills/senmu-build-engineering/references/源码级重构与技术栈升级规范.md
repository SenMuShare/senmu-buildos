# 源码级重构与技术栈升级规范

本规范用于旧系统重启、历史项目现代化、技术栈升级和中后台重构场景。典型项目特征：

- 历史系统已经交付过，但文档、人员和业务记忆不完整。
- 项目负责人要求功能不能丢，但允许更换框架、UI 和代码结构。
- 旧代码包含真实业务逻辑，PRD 或聊天描述只能作为辅助。
- 中后台页面多，存在隐藏页、弹窗、图表、权限按钮和接口细节。

## 本页导航

1. 重构类型；2. 事实来源；3. 禁止方法；4. 迁移矩阵；5. 单页迁移；6. 中后台专项；7. 后端升级；8. 新增功能；9. 验收标准；10. 关键判断。

核心原则：

```text
旧功能以源码为准，新技术栈只负责重新表达。
```

## 1. 先定义重构类型

AI 或研发接手后，先判断本次工作属于哪一类：

| 类型 | 定义 | 允许方式 |
| --- | --- | --- |
| 新产品原型 | 没有可用旧源码，以业务目标为主 | 可以按 PRD 和设计稿实现 |
| UI 翻新 | 业务和接口基本不变，只换视觉 | 旧功能逐项对照，UI 可优化 |
| 技术栈升级 | 旧框架升级或跨框架重写 | 源码级迁移，不能按需求猜 |
| 业务重构 | 业务流程也要改变 | 必须先出需求变更和验收口径 |

如果项目负责人说“功能逻辑不能变”“代码级重构”“一个页面一个页面迁移”“不能漏功能”，默认按“源码级迁移”执行。

## 2. 源码级迁移的事实来源

需求来源优先级：

1. 旧路由、菜单和页面入口。
2. 旧页面源码。
3. 旧接口封装和后端路由。
4. 旧后端控制器、模型、服务、helper、中间件。
5. 旧数据库表、字段、枚举和状态。
6. 旧线上或本地可运行页面截图。
7. 历史 PRD、接口文档、聊天说明。

如果源码和文档冲突，先以源码为准，并把冲突列为待确认问题。

## 3. 禁止的错误方法

源码级重构时禁止：

- 只读 PRD 后重新写一套功能。
- 用 mock 骨架冒充迁移完成。
- 只迁移主菜单，不迁移隐藏详情页。
- 只迁移表格，不迁移弹窗、批量操作、图表和权限按钮。
- 只迁移前端页面，不读后端方法和数据库字段。
- 把旧接口地址、参数语义、状态枚举随意改名。
- 因为新 UI 模板没有某功能，就静默删除旧功能。

## 4. 必须建立迁移矩阵

开始写业务代码前，先建立迁移矩阵。

迁移任务的总体边界、阶段、进度和恢复入口写入项目声明的 Durable Task State Owner；采用 BuildOS 新项目默认实例时使用 `governance/tasks/TASK-<NNNN>-<slug>.md`。迁移矩阵只保存路由、接口、数据模型和页面覆盖事实。

推荐文件：

```text
governance/migration/
  ROUTE_MATRIX.md
  API_MATRIX.md
  DATA_MODEL_MATRIX.md
  PAGE_MIGRATION_TEMPLATE.md
```

中后台至少要有：

- 旧路由。
- 旧页面标题。
- 旧源码路径。
- 新路由。
- 新源码路径。
- 父级菜单。
- 是否隐藏页。
- 旧接口列表。
- 表格列、筛选项、按钮、弹窗、跳转、图表、权限条件。
- 当前迁移状态。
- 未迁移项和风险。

每个旧页面必须有状态：未开始、迁移中、已实现、已验收、延后。延后必须写原因，不能消失。

## 5. 单页迁移流程

每个页面按以下顺序执行：

```text
旧路由定位
  -> 旧页面源码逐段阅读
  -> 旧 API 和后端方法提取
  -> 旧数据字段和状态提取
  -> 单页迁移记录
  -> 新页面实现
  -> 旧页面和新页面并排验收
  -> 更新矩阵、测试和工作日志
```

“逐行代码”不是机械翻译旧语言，而是逐行阅读并确认旧业务语义。每个旧方法、状态判断、接口调用和用户操作都要有去向：

- 已迁移。
- 合并迁移。
- 暂缓迁移。
- 废弃待确认。

## 6. 中后台 Ant Design Pro 升级规则

React/Web/中后台系统默认优先：

- Ant Design：基础 UI。
- Ant Design Pro：中后台整体风格、布局、典型页面模板。
- ProComponents：ProLayout、ProTable、ProForm、PageContainer 等高级业务组件。
- Ant Design Charts / AntV：常规业务图表，优先保持 Pro 视觉一致。
- Ant Design X：AI 助手、聊天、智能输入和流式输出界面。

执行规则：

- 能用 Ant Design Pro / ProComponents 拼装的，不手写通用后台组件。
- 表格页优先 ProTable 或 Ant Design Table。
- 表单页优先 ProForm 或 Ant Design Form。
- 页面容器、面包屑、菜单、顶部栏优先 ProLayout / PageContainer。
- 常规趋势、占比、排行、对比图优先 Ant Design Charts / AntV。
- 只有 Ant Design Charts 难以表达的复杂图表，才引入 ECharts。
- AI 助手界面使用 Ant Design X。AI 是新增功能时，必须单独标记，不要混入旧功能迁移完成度。

依赖选择必须做审计：

- 新增 ProComponents、Ant Design X、Charts、ECharts 等依赖后，运行依赖审计。
- 如果成熟组件存在安全审计风险，记录风险、版本、替代方案和是否接受。
- 不能因为审计风险就回到手搓组件；应优先找安全版本、overrides、替代组件或分阶段引入。

## 7. 后端源码级升级规则

后端重构不能只看接口文档。

必须读取：

- 路由文件。
- Controller / Handler。
- Service / Helper。
- Model / ORM。
- Middleware / Guard。
- Validator / Request 参数处理。
- 数据库表结构和状态字段。
- 定时任务、异步任务、回调、支付、短信、上传等边界代码。

迁移到新后端框架时，必须记录：

- 旧接口地址。
- 新接口地址。
- 是否兼容旧地址。
- 请求字段映射。
- 响应字段映射。
- 状态枚举映射。
- 权限和数据范围规则。
- 旧方法迁移状态。

禁止在没有旧代码映射的情况下凭空设计新接口替代旧接口。

## 8. 新增功能处理

源码级迁移项目允许新增功能，但必须与旧功能迁移分开管理。

新增功能要求：

- 在 ROADMAP 或 PRD 中标记为新增。
- 不计入旧功能迁移完成度。
- 不改变旧功能验收标准。
- 如果新增功能使用 AI、图表、报表或自动化能力，必须说明它读取哪些业务对象、权限边界和安全限制。

示例：

- 旧后台没有 AI 助手，新系统新增 AI 助手。
- 旧功能仍按源码迁移。
- AI 助手页面用 Ant Design X 建界面骨架。
- 真实智能能力后续再按接口、权限和审计规则实现。

## 9. 验收标准

单页验收：

- 旧页面可打开或有旧截图/源码证据。
- 新页面可打开。
- 表格列、筛选项、按钮、弹窗、详情、跳转、图表和权限条件逐项对齐。
- 旧接口和新接口映射已记录。
- mock 字段与旧接口字段一致。
- 浏览器无关键布局错误和控制台错误。

阶段验收：

- 迁移矩阵更新。
- 未迁移项明确。
- 质量门禁运行。
- 工作日志记录修改、验证、风险和下一步。
- 项目负责人能看到旧版和新版对比依据。

## 10. 关键判断句

遇到旧系统重构时，AI 必须先问或确认：

- 这是新产品重做，还是旧源码级迁移？
- 旧功能是否允许删除或合并？
- 旧接口地址是否必须兼容？
- 新 UI 是允许换风格，还是必须保留旧视觉？
- 哪些是旧功能迁移，哪些是新增能力？
- 是否需要同时迁移后端代码语义和数据库模型？

如果这些问题没对齐，不要急着写代码。
