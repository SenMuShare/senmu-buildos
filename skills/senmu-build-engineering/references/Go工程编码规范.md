# Go 工程编码规范

本页只保存 Go 特有的错误值、goroutine 生命周期、包语义和标准工具规则。通用职责、依赖、副作用、测试和评审仍由《源代码工程质量与 AI 协作规范》统一定义；项目的 Go 版本、模块、生成器和部署约束优先于个人偏好。

## 包与 API

- 包围绕可命名职责组织，名称短、具体并能让调用点自然表达含义；避免 `util`、`common`、`misc`、`types` 等无人拥有的杂物包，也不在导出名中重复包名。
- 接口服务于真实消费者的替换和测试边界，优先由消费方按最小需要定义；不为每个实现预建同名接口，也不传递指向接口值的指针。
- 导出 API、序列化和跨包状态说明 nil、空值、所有权和并发语义。`nil` slice 与空 slice 在普通代码可等价，但 JSON、数据库或外部契约必须由测试明确选择，不能机械统一。
- 导出标识符和非显然约束写可被 `go doc` 使用的准确注释；注释解释契约、并发、资源和原因，不复述实现。

## 错误与资源

- 普通失败返回 `error`；调用方处理、返回或在真正不可恢复的入口停止。库 API 不用 `panic` 代替可预期错误，初始化失败或内部不变量破坏使用 `panic` 时必须有明确边界。
- 只有愿意把底层错误变成调用方可依赖的 API 契约时才用 `%w` 包装；否则转换为领域错误而不暴露实现细节。需要分支处理已承诺的原因链时使用 `errors.Is`／`errors.As`，不比较拼接后的错误字符串。
- 不用 `_` 丢弃可能影响正确性或资源释放的错误。确实忽略时在最小位置说明为什么安全，并用测试或契约支持。
- 使用 `defer` 管理清理时确认注册时机、循环成本和错误处理；资源 owner 必须可发现，不能只依靠进程退出回收。

## 并发与取消

- 每个 goroutine 都有明确 owner、退出条件、取消路径和等待／观察方式。goroutine 不会因失去引用自动终止；阻塞 channel、后台循环和无人接收的结果都可能泄漏。
- 请求作用域的截止时间和取消使用 `context.Context` 沿调用链传播；不把 Context 存为长期全局状态，也不启动越过请求生命周期的无主任务。
- channel 用于表达所有权和同步，不用共享可变 map 或 slice 绕过同步。关闭 channel 的责任由发送／拥有完成语义的一方承担。

## 工具、测试与完成

- 使用 `gofmt` 和项目选定的 `goimports` 统一格式与导入；质量入口至少覆盖 `go vet`、`go test` 和 `go build`，按项目需要增加 lint、漏洞或模块检查。
- 并发、共享状态或 goroutine 生命周期变化时运行匹配的 `go test -race`；它只发现实际执行路径上的竞态，未覆盖路径和平台限制必须报告。
- 测试错误原因链、取消、超时、重复关闭、goroutine 退出、nil／空集合契约和并发竞争，不以 race 绿色替代语义审查。

完成前确认：包职责和调用点可读；错误未丢失；goroutine 可退出并被观察；Context 与资源生命周期正确；格式、vet、测试、race（适用时）和构建按项目契约运行。
