接手验收选择一个实际修改任务，沿该行找到实现、当前约束、共享能力和最近的检查，再执行获准的最小验证。找不到或需要反复读取无关模块时，修原导航或职责边界，不另建索引；路径存在不等于任务已经可执行。大表可使用 BuildOS 的 prepare_task_context.py 按精确能力名取一行，已知位置直接进入。涉及接口时链接唯一维护源和相关操作；可选 --fingerprint-contracts 只读取有界本地文件指纹并保留片段定位，不解析契约、不跟随引用，也不证明整套契约或实际行为已经核验。

只填写从真实代码和现有规则核对的路径。尚未实现的能力标为“计划中，暂无实现”；没有匹配检查时明确“验证入口尚未建立”及后续责任，不能编造地址。大模块可链接其现有说明，不复制整段源码或维护第二张完整依赖图。

只在本次改动影响能力归属、职责、实现入口、规则位置或验证入口时更新对应行，并沿路线核对实际内容。内部逻辑变化但这些事实未变时不更新本表。文档时间戳不代表已经核验；本次治理未覆盖的部分如实标明。

项目内的代码路径以项目根为准；Markdown 链接以本文件位置为准。检查命令可以指向现有测试策略，不在多处复制长命令。不要把个人绝对路径或临时行号当作长期身份。
