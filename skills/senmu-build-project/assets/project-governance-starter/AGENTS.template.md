## 开工读取顺序

1. 当前作用域的 `AGENTS.md` 已由 Codex 自动加载。任务所属模块仍不明时，只选择 `README.md`、Project Map 或项目等价入口中最短且足以定位的一个。
2. 只有任务涉及版本、发布、生产身份或回滚时才读基线与发布 owner；涉及分支、并行目录或实施基线时才读 Git／worktree owner。
3. 进入目标单元后遵守更深层 `AGENTS.md`，只读目标仓入口和当前任务命中的专业 owner。项目自有 Agent 仅在任务确实命中时读取其登记和定义。
4. 已有跨阶段任务时读取其 Durable Task State；没有时不为普通工作补建任务体系。
5. 项目本地规则已经充分回答普通任务时，不调用 BuildOS；缺失、冲突、结构演进、高风险门禁缺口或用户明确要求治理时，才加载一个匹配的 BuildOS Skill。

不得把多份全局文档串成所有任务的固定前置链，也不在本入口枚举全部 BuildOS Skill 职责。

## 冲突处理

- 当前项目的真实运行证据和 active 专业 owner 决定项目事实；项目明确覆盖项优先于 BuildOS 通用默认。
- 项目规则疑似过时、多个项目 owner 冲突，或覆盖会降低 BuildOS 声明的不可放弃 Hard Gate 时，不自行挑选，向用户报告具体冲突并请求裁决。
- 裁决后只更新一个项目权威 owner；本文件继续只保留导航或必要覆盖，不复制完整正文。
