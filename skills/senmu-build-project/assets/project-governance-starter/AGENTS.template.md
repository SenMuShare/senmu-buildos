## 开工读取顺序

1. 阅读 `README.md`、`governance/GOVERNANCE.md` 与 `.senmu-buildos/config.json`，确认项目原则、分类、布局、启用模块和权威根。
2. 阅读 policy 声明的项目地图和任务 owner（如存在）；当前工作已有编号计划时，再读取对应 `TASK-<NNNN>-<slug>.md`。`core` 没有专用任务体系时沿用 README、Issue 或外部任务系统，不自行补建目录。
3. 定位本次工作的责任主体、状态源、公开入口与交付单元，只加载命中的需求、工作流、实验、工程、测试、Git、版本或部署文档。
4. policy 声明了工作日志或经验 owner 时才读取；历史记录不得覆盖当前任务记录或更高层权威事实。
5. 检查真实目录、运行状态和既有实现，再开始修改或生产；需要分步骤、分阶段、跨 Agent 或跨会话的工作必须维护编号任务计划。
6. 当前任务涉及项目自有 Agent／系统提示词且 policy 启用了 `agents` 模块时，再读取 `agents/AGENT_REGISTER.md` 和命中的 `agents/{agent-key}/AGENT.md`；不要把本入口当作业务 Agent 定义。

## 稳定规则

- 新建文件、目录、模块、组件、流程或版本前，先搜索项目地图、既有实现、共享能力和 legacy 边界；能归入现有责任主体时不得另建平行实现。
- 项目本地现行规则和真实运行/交付事实优先；发现冲突时报告并修正正确的权威来源，不自行选择方便的一份。
- 输入、可重建中间物、运行状态、最终交付、证据/回执和归档必须保持可区分。
- 启用代码模块时，遵守项目实际存在的代码质量、架构、语言/框架规则和统一质量命令；`core` 不因模块启用自动生成独立工程文档。
- 不覆盖他人未提交改动，不夹带无关重构，不把临时目录、POC、mock 或局部成功冒充正式结果。
- 安全、隐私、权限、生产数据、破坏性操作和正式发布门禁不得静默降低。

## 完成输出

- 实际修改或生产范围，以及最终结果位置。
- 实际运行的验证、验收或质量命令及结果。
- 更新的需求、状态、交付、版本、日志或权威文档。
- 未完成、未验证、不适用项和残余风险。
