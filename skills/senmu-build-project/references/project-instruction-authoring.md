# Project Instruction Authoring

**Read as needed:** [Authoring](#dual-track-instruction-authoring) · [Principles](#distill-core-working-principles) · [Updates](#adopting-a-buildos-update) · [Verification](#verification-policy-adoption) · [Language](#project-instruction-language) · [Checks](#scoped-authoring-checks)

Own project collaboration, not business-agent definitions. Specialists retain methods. Optimize correct delivery and total cost, not entry length.

## Dual-Track Instruction Authoring

Reconcile existing instructions and adopt missing applicable principles; inventory alone is insufficient.

1. Find effective ancestors/overrides, host entrypoints and writable scope. Record unread/import candidates, not presumed loading. Assessment is not deletion authority. Protect global settings, history and others' work.
2. Reconcile original owners; preserve meaning, commands and exceptions. Merge equivalents, route volatile facts, remove unconditional preloads—not constraints.
3. Adapt the [AGENTS starter](../assets/project-governance-starter/AGENTS.template.md), not its headings. Keep general principles for non-code projects and applicable software clauses only.
4. Add confirmed facts and conditional routes, never invented commands/authority or defects-as-policy. Entries keep decisions; owners keep methods/configuration. Principles need no extra Skill call.
5. Finish authorized repairs and affected consumers; audit-only remains read-only. Report changes, coverage, checks and gaps.

Use one body with scoped differences. Inspect ancestor/global/Kernel inputs; keep necessary safety overlap, not full-template Hook injection or deduplication machinery. Preserve worktree reachability; files/imports prove neither loading nor permission.

## Distill Core Working Principles

Review coverage, not a mandatory lifecycle. Add no per-action form, plan, approval, Skill call or report. Keep exceptions beside defaults.

| Decision | Meaning to retain | Owner |
| --- | --- | --- |
| Understanding | Mode, goal, scope, completion and approved reasons; facts before clarification. | Product / Project |
| Judgment | Evidence, both parties' assumptions, tradeoffs and informed choice. | Product / Assurance |
| Cause repair | Source repair, bounded repair or containment under actual constraints. | Engineering / Workflow |
| Selection | Existing sufficiency, semantic fit, reuse and usable minimum delivery. | Design / Engineering |
| Preservation | Meaning, reasons, consumers, data, others' work, recovery and justified retirement. | Project / Workflow / Delivery |
| Verification | Real outcomes, risk, valid evidence and stop conditions, including non-code work. | Engineering / Design / Assurance |
| Completion | Unfinished scope; distinguish produced, verified, accepted and released. | Project / Delivery |
| Learning | Compare effort with outcomes/uncertainty; change ineffective methods, verify correction and repair the existing owner. | Learning / current task owner |

Preserve outcomes, authority and protections. Root repair grants no redesign; small scope still needs adequate repair. Non-emergency bounded repair is valid. Keep material causes, limits and revisit conditions at existing task/debt owners, not speculative risk lists; never bypass rules.

For software, recover flows/design reasons and [Contracts](../../senmu-build-engineering/references/api-and-boundary-contract-governance.md); local work needs no HTTP. Engineering owns [methods](../../senmu-build-engineering/references/source-code-quality-and-ai-collaboration.md#5-ai-implementation-debugging-and-review-loop), Product version docs. Disclose missing routes.

## Adopting a BuildOS Update

Plugin updates do not rewrite projects. Authorized adoption compares effective rules, stack, risk and host loading.

- Unused languages/equivalent rules need no edit; preserve language, exceptions and working imports.
- Technical/security changes stay at professional owners. AGENTS keeps short decisions, actual commands and conditional routes, not copied profiles.
- Record `adopted`, `no_change_needed` or `gap_open`, owner/evidence in existing task/governance records.
- Initializer `adoption_checks` remain pending; `adoption_record_owner` locates results. `active` scaffolds/structural passes prove neither adoption nor safety.
- Verify the changed route and matching check; observe affected host loading in a fresh session when available. Disclose gaps; continue independent authorized source work.

Unchanged governance is a semantic no-op. No layout-driven reinitialization or business-agent lifecycle changes; calibrate drafts first.

## Verification Policy Adoption

Use [Testing](../../senmu-build-engineering/references/software-testing-and-quality-verification.md#0-minimum-sufficient-verification): focused commands, expansion triggers, CI/release owners. Reconcile redundancy without bypassing checks or output/schema/security contracts. No bulk deletion, compulsory inventories or universal frameworks.

Adopt goal/evidence/next-action comparison, not product/error/hierarchy/failure-count rules. Preserve task systems and exceptions; check healthy progress and unfamiliar causes. Entries carry concise execution/recovery decisions; execution methods stay on task routes, not compulsory authoring reads. Installation is not adoption.

Calibrate existing runner stages, failed/affected-path selection, isolation and recovery. Reuse native records, not wrappers/fingerprints/per-test approvals. Pre-business failure is not product failure; empty discovery is not a pass. Non-code checks rendered artifacts, source accuracy, completeness or delivery. State unknowns.

## Project Instruction Language

Methods/starters use English. Explicit document-language requests prevail; otherwise preserve established/scoped languages. New files use collaboration language, then request language, else English. Nationality, market or chat alone authorizes neither translation nor bilingual copies.

Retain meaning, scope, must/prefer/may, exceptions and authority; preserve commands, paths, keys and identifiers. Code-comment, product-content and response languages are separate. Ask only about consequential unknowns.

## Scoped Authoring Checks

Use [decision scenarios](../../../tests/behavior/core-working-principles.md): triggers, non-triggers, exceptions, ambiguity, bounded repair and non-code acceptance. Check rendering, scope, originals, placeholders and markers; prose matching is not intent proof.

Separate storage/resident/task inputs. Inspect ancestors, imports, Kernel and references; imports need not reduce context. Deduplicate without losing safeguards. Context units are estimates, not official limits/tokens. No universal cap, ledger or wholesale rewrite.

Fixtures prove neither reconciliation, localization nor adherence. Observe activation; compare acceptance/model/host/tasks. Separate source review, behavior and measured savings.
