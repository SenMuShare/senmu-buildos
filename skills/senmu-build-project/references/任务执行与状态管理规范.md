# 任务执行、计划与状态管理规范

本规范管理需要分步骤、分阶段或跨会话推进的工作。任务计划属于具体项目，不属于聊天记忆，也不由专业 Skill 私有维护。需要这类恢复能力的项目必须声明 Durable Task State Owner；BuildOS standard/release 新项目默认使用编号任务计划文件，core 与成熟项目可映射可信 README、Issue、数据库、计划文件或外部系统。

## 1. 默认位置

```text
governance/tasks/
├── TASK_REGISTER.md
├── TASK-0001-<slug>.md
├── TASK-0002-<slug>.md
└── TASK-0003-<slug>.md
```

软件项目中的 `governance/` 位于 Git 仓库根。非软件／物料型项目中的同一结构位于唯一 Git 仓库 `00-project-system/` 内；大型输入、中间物、运行数据库、交付物和归档留在项目系统外。

`TASK_REGISTER.md` 只保存任务索引和当前状态。每个 `TASK-<NNNN>-<slug>.md` 是该任务的持久计划与状态记录；不为普通任务建立同名目录，也不默认附带 Discussion、Decision、Research、Validation 或 reviews 子文件。

## 2. 什么时候建立编号任务计划

满足任一条件时建立：

- 需要多个实质步骤、阶段或检查点推进，并需要持续记录进度。
- 预计跨会话、上下文压缩、人员或 Agent。
- 需要持续保存范围、非目标、授权、禁止事项或写入边界。
- 会产生多轮讨论、需求／技术评审、POC、分批实施或复杂验证。
- 属于 G3-G4，或失败涉及发布、生产、权限、数据、支付、隐私、迁移、回滚或破坏性风险。
- 用户明确要求建立可跟踪、可恢复的项目计划。

单个立即完成、可逆且无需持续跟踪的小动作可以不建。任务中途扩大到以上范围时，当时补建编号计划文件，记录当前有效事实和下一步，不追抄完整聊天。

## 3. 编号任务计划职责

任务计划文件至少保存：

1. 任务 ID、名称、状态、负责人和更新时间。
2. 目标、完成定义、范围、非目标和受影响发布／交付单元。
3. 当前约束、来源、授权、允许与禁止的操作边界。
4. 自然阶段、当前进度、结果／证据和下一步。
5. 需求、工作流、工程、交付、审查和实验的正式 owner 链接。
6. 会影响后续执行的讨论结论、任务级取舍、未决问题和重新评估条件。
7. 研究与验证摘要、未验证项和残余风险。
8. 恢复入口、收口、发布／交付／回滚状态。

任务计划是协调入口，不复制正式需求、技术设计、代码、运行状态、实验、审查报告或发布事实。重要产品取舍进入 REQ／PRD；长期技术决定进入 TD／ADR；正式评审、POC、测试和发布证据进入对应专业 owner。

## 4. 计划拆分保持够用

- 按能够说明清楚的阶段结果拆分，不按文件数量、代码层级或固定用户故事模板机械拆分。
- 每个阶段只需说清结果、进入下一阶段的完成判断和真实前置条件；没有前置依赖时写“无”，不绘制依赖图。
- 一次只执行当前上下文能够完成、验证和交接的阶段；阶段结束后更新实际结果、证据、未完成项和下一步。
- 需求、问题修复、工作流调整、媒体交付、POC 和治理任务使用各自自然表达，不强制转写为用户故事。
- 不固定创建 Setup、Foundation、Polish 等阶段，也不把脚手架、通用平台或门禁建设排在价值闭环之前。

只有准备同时交给多个执行者时才说明并行边界。并行前确认各自结果、共享状态、重叠写入范围和汇总责任；并行不自动授权创建分支或 worktree。

### 4.1 工作保持的依赖调度

- 遇到其他 Agent、CI、人工验收或外部系统未完成时，先判定它只阻塞哪个下游步骤，以及是否会争用同一分支、文件、数据库、端口、部署目录或生产对象。不用“别人还没完成”代替真实依赖。
- 默认保持工作：先耗尽当前授权内可独立开发、文档化、静态检查、构建或准备的阶段，只把真正依赖外部结果的步骤标为等待。结果会改变方案、共享资源存在冲突，或下一动作不可逆时，才暂停相关部分。
- 用户暂时不在、未回复进度消息或没有实时监督，不会撤销已有授权。执行者继续完成原范围内不需新决策的工作；只在用户明确要求暂停，或需要新权限、范围选择、费用、发布、生产、删除等新授权时停下。
- 当所有其他可执行阶段都已完成，只剩外部依赖时，把 checkpoint、所等结果的稳定身份、唤醒入口、超时／升级条件和下一动作写回任务 owner，然后释放当前空转执行链。优先由事件或后续消息唤醒；只有短时、有界工具调用或必须实时监督的高风险运行才保持当前等待。不重复轮询无变化状态，也不反复向用户发送“仍在等待”。

## 5. 会话计划与正式事实

Codex 会话 plan 只服务当前会话调度。编号任务计划是项目本地、可跨上下文恢复的计划；两者不机械双写。已有编号计划时，会话 plan 只反映当前阶段，并在阶段变化后把真实结果更新回项目任务计划。

正式 owner：

- 产品事实：`product/USER_REQUIREMENTS.md`、`versions/<version>/PRD.md`、`product/PRODUCT_SPECIFICATION.md` 或项目登记的等价产品系统。
- 正式技术设计：`engineering/designs/TD-<NNNN>-<slug>.md` 或项目既有工程 owner。
- 长期架构决定：`engineering/decisions/ADR-<NNNN>-<slug>.md`。
- 正式工作流：`workflows/` 或项目登记的 Workflow Contract。
- POC：`experiments/EXP-<NNNN>-<slug>/`。
- 正式需求／技术评审：对应 Product／Engineering review owner。
- 版本、制品和发布：`delivery/`、Release Plan 与 Release Record。
- 可复用经验：项目声明的 Lessons Learned Register。

讨论、研究、决定和验证的普通摘要直接写在任务计划中；只有它们本身成为需要长期维护、独立评审或复用的正式产物时，才进入对应专业 owner。

## 6. 状态与更新点

统一状态：`planned`、`active`、`blocked`、`verifying`、`completed`、`cancelled`、`archived`。

`blocked` 只用于当前范围内已无任何可继续的有意义工作，且必须等待用户决策、新授权或外部事实改变时。单个阶段或运行步骤等待时，任务可保持 `active`，但必须在计划内明确可并行阶段和唤醒条件，不让会话空转冒充进展。

至少在以下时刻更新任务计划和 Task Register：建立任务；范围、授权或完成定义变化；完成有意义阶段或评审轮次；POC 形成阶段结论；实际委派、暂停或切换会话；进入验证、完成、取消或归档。不要因每个微小文件修改频繁刷新任务表。

执行中发现新信息时，按事实类型更新：

| 变化 | 必须更新的位置 |
| --- | --- |
| 用户行为、产品范围、业务规则或验收 | REQ／PRD 或项目既有产品 owner |
| 模块、公共接口、数据、依赖、基础设施或长期技术路线 | TD／ADR 或项目既有工程 owner |
| 工作流输入输出、步骤、状态、恢复或回执契约 | Workflow Contract 或项目既有工作流 owner |
| 执行顺序、当前阶段、委派、暂停或恢复位置 | 编号任务计划或项目既有任务系统 |
| 局部实现细节且不改变以上契约 | 代码、测试和必要注释 |

Work Log 记录发生过什么；编号任务计划保存当前有效计划和状态。二者不得互相替代。

## 7. 收口与归档

任务进入 `completed` 前，核对最初承诺、已批准变化、当前正式 owner、实际结果和验证证据：

1. 正式需求、技术设计、ADR、工作流、实验决定、评审和交付事实已写入各自 owner。
2. 实际结果覆盖承诺范围；未完成、部分完成、范围外新增和取消项状态明确。
3. 匹配验证已经执行并链接证据；未运行和无法覆盖部分已说明影响。
4. 任务计划只保留必要的当前状态、关键决定摘要和追踪链接；重复正文与临时内容已经清理。
5. 未验证项、残余风险、发布和回滚责任已经说明。

`completed` 只表示本任务定义的结果和收口条件满足，不替代 `implemented`、`accepted` 或 `released` 等专业事实。默认保持编号计划文件稳定路径，用状态 `archived` 表示只作历史参考；确需离线归档时先更新 Task Register 和全部引用。

## 8. Hook 与成熟项目

Hook 不注入完整任务计划，不把聊天推断写成持久规则。只有真实验证证明恢复入口仍频繁丢失时，才评估注入 Task ID、硬边界和计划文件路径的短摘要。

成熟项目已有可信任务系统时，登记其 owner、对象 ID、状态语义和恢复方式，不创建第二套 `governance/tasks/`。聊天内容不能作为唯一任务状态源。

成熟项目接管专项的任务状态还应链接冻结基线、审查 Finding、用户决定、整改任务／变更身份、复核证据和临时内容去留决定。详细语义由《成熟项目接管治理专项规范》唯一维护，任务规范不复制其 schema。
