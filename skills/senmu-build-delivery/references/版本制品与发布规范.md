# 版本、制品与发布规范

本规范处理版本身份、Tag、独立制品、保留和发布收口。授权状态与生产事实读取[发布授权与生产事实协议](发布授权与生产事实协议.md)；Git／worktree 读取[代码管理与合并规范](代码管理与合并规范.md)。

## 1. 发布单元与版本身份

先判断对象能否独立构建、部署、回滚并具有独立职责。只有成立时才建立独立版本和 Tag；monorepo 内部模块不伪造发布单元。

正式发布单元至少关联产品／需求范围、必要技术变化、冻结 commit、`VERSION`、changelog、不可变 Tag、实际采用的制品、目标环境、生产验证与回滚点。这些对象必须对应，但不要求每种项目拥有全部层级。

正式版本、公开源码、部署和独立制品是可组合能力，不能由 `release` 档位、Tag 或平台自动源码快照互相推导。默认使用 SemVer；多发布单元使用稳定 scope。项目既有方案优先。创建本地 Tag、推送 Tag、平台 Release、上传制品和部署是不同状态与授权。

## 2. 候选与发布阶段

1. 确认范围、发布单元、授权和回滚条件。
2. 收口需求、实现、测试、文档和日志。
3. 更新版本与 changelog，冻结候选 commit。
4. 运行项目声明的质量、构建和候选检查。
5. 仅在授权覆盖时创建／推送 Tag、上传制品或平台 Release。
6. 仅在授权覆盖时部署并验证目标环境。
7. 追加 Release Record，记录成功、失败、部分完成或回滚。
8. 按保留策略分别收口本地、生产、远程库和 Git 执行面。

用户只要求开发、候选或预检时不得越过 `preflight_passed`。包含 Skill、Hook、路由或行为契约变化的正式发布，冻结后必须有匹配当前表面的完整性复审，且没有未关闭阻断 Finding；结构测试不能替代语义复审。

Hotfix 完成但暂不发布时，记录代码位置、验证结果、风险、同步状态和后续发布条件；不得把本地通过说成上线。

## 3. Tag、代码包与制品

- Tag 指向冻结 commit 且不可移动；它表示候选来源还是已验证发布由项目预先声明，实际结果由 Release Record 判断。
- Git 代码包不包含密钥、生产数据、上传文件、数据库、缓存、日志或未授权材料。
- 独立制品定位源码 commit、版本、平台、构建输入和校验身份。
- Git commit／Tag 只证明源码身份；只有基础镜像、依赖锁、工具链、外部输入和 provenance 可获得时，才声明制品可重建。
- Docker／二进制制品核对目标 OS／架构；名称不能替代 manifest 或运行端检查。
- 正式配置使用明确版本或 digest，不使用漂移的 `latest` 作为发布身份。

## 4. 保留与清理

默认保留当前已验证版本、一个已验证可回滚版本以及项目显式 Pin／合规证据。回滚版本不机械等于版本号相邻。项目策略可覆盖数量，但不得静默破坏回滚、数据、合规或必要证据。

清理仅作用于当前发布单元声明的受管路径和镜像仓库：

- 先按 digest／ID 核对当前、回滚、Pin 和全部容器引用。
- 不删除 Git commit、正式 Tag、changelog、Release Record、数据库、Volume、其他项目资源或全局缓存。
- 不执行跨项目全局 prune；强制删除需要单独授权。
- `dry-run` 不是正式收口；生产验证和发布授权成立后才 apply。

本机构建端、生产运行端、远程镜像／制品库和本次 Git 执行面分别登记。主机清理完成不代表远程 registry 或 Git 已收口。

## 5. 发布源与生产核验

正式制品只能从发布单元登记的权威目录和冻结 commit 构建。其他 worktree 局部通过不能代替发布源验证，其无关脏状态也不能否定候选。

目标环境至少核对实际运行对象／镜像身份、版本接口或等价身份、健康与就绪、本次变更的用户主流程，以及必要的数据迁移、权限、安全和回滚可用性。

发布完成输出包含发布单元、版本、commit／Tag、制品身份、环境、验证、回滚点、保留集合和残余风险。技术路线由 Engineering 决策；Delivery 只收口兼容、迁移、构建、部署和回滚影响。
