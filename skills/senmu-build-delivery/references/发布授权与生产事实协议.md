# 发布授权与生产事实协议

本协议用于正式交付、部署、上线、热修复、回滚和其他会改变外部环境的操作。它把发布计划、发布候选、执行授权、实际部署和生产事实分开，防止“代码完成”“预检通过”或“Tag 已存在”被误报为已经上线。

## 1. 四类对象

| 对象 | 回答的问题 | 典型 owner |
| --- | --- | --- |
| Version and Release Plan | 准备发布什么、范围和门禁是什么 | `delivery/RELEASE_PLAN.md` |
| Release Candidate | 哪个不可歧义 revision 和制品等待放行 | Git commit、CI／制品库和 Artifact Manifest |
| Release Record | 某次发布尝试实际做了什么、结果如何 | `evidence/releases/` 或项目发布系统 |
| Production Truth | 目标环境此刻真实运行什么 | 运行平台、版本接口、健康状态和用户可见流程 |

计划不是候选，候选不是授权，部署完成不是发布验证完成，发布记录也不能反向覆盖目标环境的真实状态。

## 2. 发布状态模型

推荐状态：

| 状态 | 含义 |
| --- | --- |
| `planned` | 已规划范围，尚未形成不可歧义候选 |
| `candidate` | revision、版本和候选制品已锁定，尚未放行 |
| `preflight_passed` | 声明的发布前门禁通过，但没有外部变更权限 |
| `authorized` | 用户已明确授权本次发布范围和目标环境 |
| `deploying` | 正在改变目标环境 |
| `deployed_unverified` | 部署动作结束，生产验证尚未完成或证据不足 |
| `released` | 目标环境身份、健康和受影响主流程已验证 |
| `failed` | 发布尝试失败或只完成部分动作，需先核对现状 |
| `rolled_back` | 回滚动作及回滚后的生产事实均已验证 |
| `cancelled` | 候选被明确取消，不再推进 |
| `superseded` | 候选或记录被后续版本替代，保留历史 |

状态只能前进到证据支持的位置。无法确认外部系统是否已改变时使用 `deployed_unverified` 或 `failed`，不能猜测为旧版本、成功或已回滚。

## 3. 授权边界

用户要求“开发完成”“准备发布”“做预检”“生成候选”时，默认权限上限是本地或 CI 内的可逆准备工作。以下动作需要本次任务中的明确授权：

- 创建或推送正式 Tag、发布页或正式制品。
- 上传到远端、连接生产主机、执行部署或迁移。
- 重启服务、切换流量、修改域名／配置或生产数据。
- 对外通知、上架、发布内容或清理远端回滚资源。

有效授权至少能确定目标发布单元、目标环境和允许动作；高风险发布还应明确版本／候选、服务范围、窗口和回滚边界。授权绑定精确候选的一次有限发布会话，不是永久通行证，也不是机械限制为一条命令。过去发布过、拥有凭据、脚本可执行或计划中写着“发布”都不构成本次授权。

授权可由用户自然语言和项目已登记事实共同确定，不要求用户枚举技术动作：项目只有一个当前发布单元、一个默认生产环境和一条标准发布入口时，“发布最新版本／把这批修复发布”是明确的标准发布授权，覆盖该入口已声明的常规版本提交、不可变 Tag、既有 Remote 同步、平台 Release、制品、部署、生产验证和 Release Record。它不自动覆盖首次创建远程资源、额外付费服务、不可逆迁移、计划外数据／制品删除、跨项目动作或未声明环境。

项目存在多个发布单元或环境、纳入范围不明，或标准入口会触发上述额外高风险动作时，只向用户询问那个会改变结果的选择；确认后由 Delivery 自行决定合并、版本和 Tag 顺序。不得把“请逐项授权 commit／Tag／push／deploy”当作安全流程转嫁给非技术用户。

执行前先识别本地 Git、Remote、托管平台和部署目标分别是否存在。没有 Remote 时允许形成完整本地版本，不创建远程仓库。用户只授权某个技术层级时不得向外扩张；用户授权项目标准发布时，由已声明标准入口决定既有 Remote、正式 Tag、平台 Release 和部署中哪些层级适用。

项目发布计划已经明确保留策略、受管对象和环境时，本次正式发布授权可以覆盖该项目级标准收口。用户明确指定不同保留数量或周期时，记录为项目策略并优先采用；若会失去已验证回滚点、违反合规或删除必要证据，先说明影响并取得对应风险确认。授权不能外推到未声明仓库、其他项目、Volume、数据库、Git 历史或全局缓存。远程镜像／制品库清理属于外部变更，只有计划和授权明确覆盖时执行；所有收口只能在生产身份、健康和受影响主流程验证通过后由唯一发布入口触发。

同一候选、制品和环境内，无副作用且生产状态明确的连接、上传或查询失败可以在项目重试预算内恢复，不要求用户重复授权。候选 revision、制品内容、目标环境、迁移方案、回滚边界变化，普通发布切换为 Hotfix，或生产状态变得不明确时，原授权失效并重新确认。

用户明确说“不要发布／先别上线”时，将其作为发布授权约束写回项目已有任务或发布 owner，默认作用于发布单元和目标环境，可再限定版本线或批次。它不会因换会话、代码提交、集成、预检或一次发布失败自动解除；Hotfix 只能获得绑定精确 commit 和回滚点的局部放行，不解除其他批次的限制。

## 4. 候选与制品身份

发布候选至少锁定：

- release unit、版本、源 commit／revision 和发布基线。
- 制品 ID、哈希、目标平台、构建入口和构建环境。
- 配置／schema／迁移版本及兼容要求。
- 本次范围、明确不涉及范围和联动发布单元。
- 质量证据、未验证项、已知风险和回滚候选。

正式 Tag 只表示已经验证的正式发布，指向不可移动的冻结 commit，并由 Release Record 关联目标环境或公开渠道证据。部署前候选使用 commit、候选编号和 Artifact Manifest；创建或推送正式 Tag 仍属于发布动作，未经授权不得执行。

可使用 [Artifact Manifest 模板](../assets/delivery-governance/ARTIFACT_MANIFEST.template.json) 记录候选制品；已有制品库完整保存 provenance、哈希和平台时，只登记查询入口，不创建同步副本。

## 5. Release Record

每次实际发布或回滚尝试使用独立 `release_id`，并至少关联：

- 授权时间、授权人／来源和授权范围。
- release unit、环境、版本、commit、Tag 和制品哈希。
- 开始／结束时间、执行入口、操作者和实际动作。
- 数据备份／迁移、配置变化、服务或流量变化。
- 每个门禁、健康检查、版本核对和主流程验证的结果与证据。
- 失败点、部分成功、生产现状、回滚决定和未完成事项。

Release Record 是追加事实，不静默改写失败尝试。可使用 [Release Record 模板](../assets/delivery-governance/RELEASE_RECORD.template.md)；外部发布系统已经提供等价记录时保留对象 ID 和可查询链接。

## 6. 生产事实判定

发布状态以目标环境为准，按发布单元选择足够的证据组合：

- 平台或编排层实际运行的 deployment、镜像 digest、包版本、静态资源 revision。
- 应用公开版本接口、build metadata 或等价运行身份。
- 健康、readiness、依赖连接、启动日志和错误率。
- 本次变更影响的用户可见主流程或业务接口。
- 数据迁移、队列、定时任务、缓存和外部集成的实际状态。

本地测试、候选文档、Git Tag、CI 绿色、制品上传成功、单个健康接口或部署命令退出 0 都不能单独证明 `released`。证据冲突时保持未验证，先调查目标环境，不让文档覆盖运行事实。

## 7. 失败、部分部署与回滚

- 发布命令中断后先盘点所有受影响服务、配置、数据和流量，再决定继续或回滚。
- 回滚必须分别处理代码／制品、配置、schema／数据和外部副作用；数据库迁移不可逆时不得把“重新部署旧镜像”称为完整回滚。
- 备份只有在身份、完整性、保留位置和恢复入口可验证时才算回滚依据；重要数据变更应有恢复演练或等价证据。
- 回滚后重新验证目标环境版本、健康和受影响主流程，再标记 `rolled_back`。
- 失败记录、事故证据和原 release_id 必须保留；新一轮发布使用新的 release_id。

## 8. 与其他状态的边界

- 产品 `accepted` 由 Product owner 判定，不自动授权发布。
- 工程测试由 Engineering owner 提供质量证据，Delivery 只决定是否满足本次发布门禁。
- Workflow Run Manifest 记录生产链路内部运行事实；正式上线尝试由 Release Record 负责。
- Task Plan & Status Record 保存跨阶段计划、进度和以上对象的链接，不复制发布记录正文。
- Hook 不读取凭据、不执行发布，也不根据会话阶段自动授予权限。

## 9. 收口检查

- 当前状态没有超过证据和授权边界。
- 候选 revision、版本、Tag、制品、配置和目标环境可一一对应。
- Release Record 能还原所有外部动作、验证、失败和回滚决定。
- 生产身份与用户可见主流程已经从目标环境核对。
- 未发布、未验证、失败和已回滚保持不同状态。
