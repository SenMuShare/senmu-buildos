# 部署测试与安全规范

本规范面向需要部署或正式交付的项目，规定部署文档、发布验证和运行环境安全边界。单元、集成、契约、端到端测试设计由 `senmu-build-engineering` 的软件测试规范负责；本页只判断这些证据是否满足当前发布门禁。

## 本页导航

1. 部署文档与发布后核对；2. 资源与制品；3. 测试与验收；4. 安全与敏感信息；5. 高风险功能检查。

## 1. 部署文档要求

部署文档必须包含：

- 本地启动方式。
- 正式环境或测试环境说明。
- 依赖服务。
- 环境变量和配置文件。
- 密钥、证书和私密配置如何存放。
- 构建命令。
- 部署命令。
- 健康检查方式。
- 发布后核对清单。
- 回滚方式。
- 哪些脚本是日常发布，哪些只用于首次初始化或灾备恢复。
- 制品构建、上传、保留和清理策略。
- 服务器硬件资源约束，例如磁盘、内存、CPU、镜像数量、日志保留周期。

部署文档最后必须有 Checklist：

```markdown
## 发布后核对清单

- [ ] 线上健康检查通过
- [ ] 线上版本号正确
- [ ] 核心页面可访问
- [ ] 核心 API 可用
- [ ] 线上实际运行的镜像、包或静态制品版本正确
- [ ] 如果使用 Docker，服务器侧镜像架构与生产服务器匹配
- [ ] 本次改动涉及的主流程已验证
- [ ] 日志中没有明显启动错误
- [ ] tag / VERSION / changelog 一致
- [ ] Bug/Hotfix 已确认 patch 版本、回滚点、线上修复路径和未发布改动说明
- [ ] 未发布改动已说明
- [ ] 已知风险已记录
```

发布不能只写“部署完成”。必须写清楚验证结果。

发布验证不能只看本地构建结果。凡是通过制品上线的项目，发布后必须在目标环境验证实际运行对象，例如：

- Docker：容器使用的镜像 tag、镜像架构、容器启动时间和健康检查。
- 静态站点：线上文件时间、关键页面 HTTP 状态和关键静态资源是否来自本次构建。
- 后端服务：版本接口、健康检查、日志启动记录和依赖连接状态。

如果部署脚本中途失败但部分服务已经被替换，必须先确认线上当前状态，再决定回滚或重新发布，不能直接假设线上仍是旧版本。

## 2. 资源与制品管理

制品身份、默认保留集合、项目策略覆盖、本机构建端／生产运行端／远程仓库和 Git 执行面收口由[版本制品与发布规范](版本制品与发布规范.md)唯一规定。本页只要求部署设计把这些策略落到真实环境，避免磁盘、镜像、缓存和日志无限增长。

部署侧必须确认：

- 每个实际存在的资源面都有受管范围、保留策略、磁盘上限、dry-run、清理入口和回执；不存在的远程仓库等资源面不伪造。
- 当前运行对象和已验证回滚对象在清理前真实存在，镜像优先核对 digest／ID，不只看可移动 tag。
- 更早 tar、旧镜像、临时上传文件和 dangling 对象只有能精确归属本发布单元时才清理；不执行跨项目全局 prune。
- 日志和上传缓存要有保留周期，不能无限堆在服务器。
- 如果服务器资源很小，优先采用本地构建制品、上传服务器加载的方式，避免服务器现场构建消耗 CPU、内存和磁盘。

部署文档中必须说明：

- 制品命名规则。
- 制品保存路径。
- 项目保留策略及其来源；未声明时使用 BuildOS 默认回滚基线。
- 清理命令或清理策略。
- 回滚时从哪里取版本。
- 是否允许服务器现场构建。

## 3. 测试与验收

发布验收应从工程测试策略引用与本次影响匹配的证据，至少区分：

- 单元/组件测试：验证函数、组件、边界状态。
- 接口/业务测试：验证权限、计费、数据隔离、异常分支。
- 真实流程测试：验证用户从入口到完成主任务的完整路径。

Mock 使用边界：

- 可以用于组件状态、第三方服务异常、纯函数边界。
- 不能替代上传、支付、导出、权限、文件处理、播放器、订单、AI 任务等主流程验收。

验收时必须说明：

- 本次影响了哪些路径？
- 哪些路径已经测试？
- 哪些路径没有测试？
- 未测试的风险是什么？
- 是否需要线上验证？

Bug/Hotfix 验证通过后必须追加发布门禁判断：

- 是否已更新对应版本号和 changelog。
- 是否已写工作日志，记录原因、修复、验证、风险和下一步。
- 如果发布，是否已有 tag、制品、线上验证和回滚点。
- 如果不发布，是否已记录不发布原因、代码位置和后续发布条件。

## 4. 安全与敏感信息

默认不得进入 Git：

- `.env`、`.env.*`
- API Key、AccessKey、Secret、AppKey。
- 支付密钥、证书、私钥、SSH key。
- 用户上传文件。
- 数据库文件。
- 真实生产数据。
- 本地运行数据。
- 服务器私密配置。

允许提交：

- `.env.example`。
- 脱敏配置模板。
- 不含密钥的部署脚本。
- 脱敏后的技术文档和测试说明。

涉及账号、权限、支付、上传、删除、导出、管理员操作时，必须以后端校验为准，前端隐藏按钮不等于权限控制。

## 5. 高风险功能检查

以下功能必须特别检查后端边界：

- 登录、注册、密码重置。
- 管理员操作。
- 支付、订单、退款、余额。
- 文件上传、下载、导出、删除。
- 用户数据隔离。
- 第三方服务密钥。
- AI 模型调用和费用统计。
- 公开静态文件访问。

AI 助手或研发人员如果发现这类功能只靠前端隐藏按钮、前端校验或 mock 数据完成，应停止并补后端校验。

Delivery 发现上述实现缺口时应阻断候选并移交 Engineering 修复；除非任务同时授权修复，不应在部署过程中临时改写业务代码。
