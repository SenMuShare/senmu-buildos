# Senmu BuildOS 用户更新日志

本页只说明每个正式版本带给用户的变化。

## [2.20.5] - 2026-09-24

### 主要更新

- 开发批次的创建、恢复、验证、评审和封存共用身份校验，避免同一个异常在不同入口得到相反结论。
- 列表默认返回有限摘要、状态数量和登记异常，支持按编号、状态及分页展开；旧版完整 JSON 可通过 `list --format full` 继续获取。

### 修复问题

- 修复历史重复编号、分支偏离原基线时，部分验证或封存入口仍能通过的问题。
- 修复登记目录已被其他仓库替代时，恢复入口仍报告成功的问题。
- 保留正常恢复缺失工作树及已回收源码位置的接收验证，不擅自清理或覆盖已有成果。

## [2.20.4] - 2026-09-24

### 主要更新

- 同一开发批次编号在一个仓库内只登记一次；重复执行相同创建命令时继续使用原位置和基线。
- 同时创建时增加短暂互斥保护，不影响已经建立的开发批次继续工作。

### 修复问题

- 修复更换分支名或目录即可重复登记同一编号、随后无法按编号恢复的问题。
- 冲突请求在创建新分支和目录前被拒绝；已结束批次的编号不能重新使用。
- 发现历史重复登记时保留原记录并明确报错，不自动删除、合并或猜测应保留哪一份。

## [2.20.3] - 2026-09-23

### 主要更新

- 可固定一个提交用于评审，而不提前结束开发批次；同批问题继续在原分支和工作树修复。
- 可按任务编号只读找回登记位置和真实状态，返修评审可直接获取相对上次提交的新增差异。
- 统一开发中检查、模块集中验收和整版候选检查的边界，不因换会话或新提交机械重跑全部验证。

### 修复问题

- 澄清评审与封口混用、同一批次返修另开分支，以及新提交导致全部证据被一律作废的指引歧义。
- 路径缺失时保留提交是否存在的独立事实，不把查找失败直接认定为成果丢失。
- 保留必要的独立审查、过期批准和高风险验证限制；工具输出只证明 Git 范围，不自动认定测试通过或业务完成。

## [2.20.2] - 2026-09-23

### 主要更新

- 任务整合回执核对冻结源码和实际接收内容，支持正常合并、压缩合并及可验证的多提交接收范围。
- 区分审查记录的格式检查与合并放行，草稿仍可检查和保存。

### 修复问题

- 修复明确要求审查时，未完成的草稿仍能返回成功的问题。
- 修复无关主线提交或仅保留历史关系的合并被误记为已整合的问题。
- 无法证明接收内容一致时保留待核实状态，不把源码整合当成产品验收或发布。

## [2.20.1] - 2026-09-22

### 主要更新

- 统一专项审计与普通自查的入口，审计范围和审查者是否独立分别判断。
- 项目可在既有合并入口明确配置自审、同行或独立审查要求；未校准的旧入口继续保留原有保护。
- 补齐长参考的章节导航，合并 AGENTS 起稿及三语 README 的重复说明。

### 修复问题

- 修复正文、模板与审查脚本要求不一致的问题；明确的独立审查要求不能通过记录内例外绕过。
- 澄清只交设计的完成条件，以及普通小改不自动触发全局治理校验的边界。
- 保留失败检查、未解决问题和过期候选的阻断，不自动改写已有项目或用户安装。

## [2.20.0] - 2026-09-22

### 主要更新

- 将系统调查、缺陷修复、设计变更和行为保持型重构整理为可直接使用的工程路径，先理解运行方式和设计理由，再修改实现。
- 正式开发版本同时保留需求与技术说明。小版本可简写，已有合并文档可使用职责分明的章节；总文档维护验收后的当前事实。
- 完善从调用方式到数据、接口和模块边界的设计方法，明确方案取舍、影响依据、真实验证和经验再利用。
- 同步项目 AGENTS.md 起稿与治理入口，保留八个专业领域、轻量任务路径和重要例外，不自动改写已有项目。

### 修复问题

- 修正版本技术说明可选与版本责任要求之间的不一致，减少规则存在但任务入口难以找到的问题。
- 澄清必要设计注释、有效测试与未知风险的保留边界，避免以删注释、测试数量或多 Agent 数量代替质量判断。

- 保留原有八项原则、适度验证与治理机制，不增加新规则或流程，也不自动改写已有项目指令。

### 修复问题

- 澄清需求回查的边界：保留尚未完成的有效目标，不恢复已取消事项，也不借收尾增加新目标。

## [2.19.0] - 2026-09-21

### 主要更新

- 对照官方 Skill 指南校准调用描述与默认提示词，明确当前任务和边界，避免无关文档、全流程或子 Agent 被自动加入。

- 修复空描述误读后续字段、重复关键字段未拒绝，以及示例链接被当作有效读取入口的问题。
- 修复项目指令模板未知变量未被识别的问题，保留合法渲染、适用范围和既有保护。

## [2.18.0] - 2026-09-21

### 主要更新

- 整合项目核心工作原则：先对齐目标和任务性质，再独立判断、权衡现实约束，并完成有证据支持的交付；不再按每个问题逐条堆叠规则。
- 让复用、成果保护和充分验证同时适用于代码与非代码项目，研发细则继续按需使用，不增加固定全流程。
- 治理沿用项目语言、有效约束和例外，保留原有业务含义；本地安装和项目采用仍分别执行。

### 修复问题

- 明确源头修复、有限修复和临时控制的适用边界，避免为了根治擅自重构，或把有限处理说成问题已经彻底消除。
- 将模板长度改为内容审阅信号，自动检查真实的变量、条件区块与渲染行为，不再用固定措辞代替原则含义；必要权限与安全保护保持不变。

## [2.17.0] - 2026-09-21

### 主要更新

- 为研发项目的协作指令加入“最小充分验证”：先复用已有覆盖，按实际影响选检查，只为真实缺口新增测试，并明确停止条件。
- 初始化和治理时对齐项目规则、真实测试命令与自动化入口，保留项目语言、必要保护和业务边界，不自动批量改写项目。
- 完善测试编写、执行、证据复用和等待方式的指导，关注正确交付与任务总成本，不以测试数量或最少文字为目标。

### 修复问题

- 将只检查测试指导固定措辞的一个用例改为语义评审场景，避免合理改写被误报；实际解析、授权和运行回归继续保留。
- 明确发布阶段复用有效源码证据并独立检查制品，减少阶段切换造成的无意义重复；实际模型表现与 Token 改善仍需项目验证。

- 补全版本准备脚本的实际更新范围，明确源码版本、不同发布渠道与本地安装不能互相替代。

- 修复重复版本、身份及状态声明互相冲突却能通过校验的问题，拒绝空值，继续排除代码块里的示例元数据。
- 保留项目语言、业务含义、权限边界与已有保护；源码检查不冒充实际召回或效果提升，更新插件不自动改写业务项目。

## [2.14.0] - 2026-09-20

### 主要更新

- 项目 AI 协作指令进一步凝练核心工作原则：独立判断、证据校准、源头改善、适用复用、清晰实现、成果保护、适度推进与按需获取上下文。
- 区分用户目标、建议方案和事实假设，同时检查 AI 自己的判断；指出重要问题与替代方案，尊重用户知情后的选择，不迎合也不机械反对。
- 优先改善正确的执行路径，不用反复叠加补丁、审批和检查代替根因修复；保留必要保护，并允许授权范围内的紧急止损。

- 将分散的核心理念纳入初始化和已有项目指令治理，不要求小修改额外经历全面评审，也不向业务 Agent 自动灌入开发协作原则。
- 保留项目语言、有效约束和明确例外，合并等价表达；没有实质变化时不反复追加或机械重写。
- 本版发布包包含新版核心原则；更新插件后仍需在目标项目发起治理，实际加载、工作效果和总任务消耗需分别核验。

## [2.13.0] - 2026-09-20

### 主要更新

- 业务 Agent 支持新建与存量内容治理：定位实际生效的提示词、整理意图和约束，并保护业务目标、输入输出、分支、模型参数和权限，不使用通用模板覆盖业务定义。
- 图像节点按需读取任务指导与模型专项参考，覆盖 GPT Image 2／2.5 以及百炼 Qwen-Image 2.0／3.0 的已核实接口；区分 Agent 工作指令、单次画面提示词与 API 配置。
- 通用业务 Agent 模板以英文维护，项目保留原有语言。结构校验兼容旧中文和英文标题，其他语言或合并章节可采用稳定标记。

### 修复问题

- 全项目治理需明确实际 Agent 范围、已检查及未评估项；不再用少数样本或标题齐全宣称完成内容治理。
- 仅编写提示词的节点不会被改成自动生图、评审或重试流程；内容优化和实际效果分开验证，无变化时不机械重写。
- 更新插件不会自动修改项目、执行付费模型或部署业务 Agent；出图效果、真实召回和上下文节省仍需项目内核验。

## [2.12.0] - 2026-09-20

### 主要更新

- 项目协作指令采用双线治理：整理已有内容，并补充适用的共同工作原则；保留项目特点、有效约束和明确例外，不再只输出审核结论。
- 共同原则覆盖复用既有能力、延续已选技术体系、简单正确且可读的实现、源头修复、适度验证、按需读取和真实直接的协作，不指定具体业务、语言或组件库。
- BuildOS 的方法与默认起稿使用英文，已有项目入口沿用原文语言；新文件优先采用项目协作语言，其次采用初始化请求语言，无线索时使用英文。保留命令、路径、标识符和约束强度，不默认生成双语副本。

### 修复问题

- 不再把“不能复制整套方法论”误解为“不能采用通用工作原则”；已有等价表达会合并，重复治理不应不断追加内容或机械改写。
- 初始化区分代码与非代码项目，不编造框架和验证命令。更新 Skill 不会自动覆盖业务项目、历史工作树或客户端配置；需要在目标项目明确发起治理，实际会话加载和 Token 效果仍须分别核验。

## [2.11.0] - 2026-09-20

### 主要更新

- POC/demo 增加项目接入：登记实验位置、记录归属、开发与发布隔离、保留和备份策略，下一位 Agent 可以按入口继续实验，而不是重新猜路径。
- 实验模板保留方案设计、每轮对比与变化原因、失败和反例、采用与否决依据、日期及复现限制；简单 demo 可用短报告，不强制创建五份文件。
- 实验结论与资源收尾分开：保留必要代码补丁、参数和代表性样例，再按已有授权处理可再获取的引擎、模型和缓存，不把实验归档当成已经清理。

### 修复问题

- 对齐旧模板的外部路径提示与结论状态，新增只读检查识别未配置、路径越界、活跃工作树重叠及错误跟踪；不擅自创建实验目录、不执行真实清理。
- 审查只读与已授权的隔离实验写入不再混淆；保留已合入的任务恢复及子代理快照身份修复。
- 旧项目沿现有实验 owner 增量接入，历史记录及旧 manifest 不自动覆盖。版本更新不等于项目已治理，也不证明实际实验结论、备份恢复或 Token 节省。

## [2.10.0] - 2026-09-19

### 主要更新

- 发布清理现在区分预览、未启用、无候选、已清理和失败；检查失败不会再伪装成“资源为零、已经完成”。按实际 Docker 环境回报结果，保留当前版、可用回滚版、显式保留项和正在被引用的资源。
- 项目治理会发现 Claude 的项目指令与规则候选，并核对真实加载方式。共享规则继续只维护一份，不自动覆盖现有 CLAUDE 文件或修改全局设置。
- 飞轮反馈明确区分“已分类”和“已解决”，可通过跟踪引用衔接已有任务；只读子代理不再被要求产生代码提交。

### 修复问题

- 维护侧公开发布支持完整候选核对和中断续接，不重置未推送的工作，也不把草稿 Release 当作正式完成。
- 升级 Skill 不会自动改写已生成到业务项目中的清理脚本；需要在项目治理或发布入口调整时同步对应模板并验证接线。此版本不执行真实设备清理、不自动上传反馈，也不宣称已完成宿主加载或实际公开发布。

## [2.9.0] - 2026-09-18

### 主要更新

- 产品源码与作者私有资料分开：使用、安装和贡献产品不再依赖作者的研发记录。
- 保留使用反馈到产品改进的流程，原始材料留在获准的数据位置，不随 Skill 安装或自动公开。
- 支持单一产品源码在维护工作区中独立定位、检查和打包，公开交付不再要求常驻第二份源码副本。

### 修复问题

- 校准目录迁移后的安装来源、验证命令和发布目标检查，避免把私有仓库历史当成公开源码。
- 修正公开检查中含空格路径样例的表达，保留原有隐私检查与安装恢复保护。
- WorkBuddy 安装改为按实际存在的数据根定位技能目录，不再写死改名前的 `.workbuddy`；安装结果会打印真实写入路径。此前装到运行中的 App 不读取的目录时，会显示安装成功但技能从未生效。

## [2.8.1] - 2026-09-18

### 主要更新

- 内部安装改为运行文件白名单，不再把任务记录、原始审查证据、冻结旧 Skill 和项目实例配置一起装入插件；所需脚本、模板、Hook 与适配器继续保留。
- 新安装载荷先准备并校验后再切换，原受管快照保留用于恢复；未知目标和符号链接不被自动覆盖，不把历史资料当作可随意删除的缓存。
- 缩短六个界面说明字段，保持触发描述不变；统一入口与详细规则的适用条件，前后端任务按问题定位和展开，不默认读取一整套清单。

- 补齐白名单根目录符号链接检查，以及 Unicode 和带空格用户目录的隐私检测；保护不会以回退整仓复制的方式绕过。
- 校正项目指令可保留必要短约束、封存父分支的受控依赖例外、治理校验器接口说明及过期任务摘要。
- 当前为源码版本更新。公开投影、公开 Tag／Release、本机安装激活、原生回收恢复和模型实际 Token 效果分别核验，本次不宣称它们已经完成。

## [2.8.0] - 2026-09-17

### 主要更新

- 项目导航升级为「能力到落地」的合同：每个受治理能力都要能找到真实实现入口、适用规则和验证入口；自动生成的目录只是草案，未校准到真实代码前不视为已完成治理，计划中的能力也不会被写成已实现路径。
- 已授权的整改可以继续在原有范围内完成，不需要每换一个阶段再申请一次批准；流程状态只描述进度和证据，不再被误读成授权或撤权。
- 同一批连续调整界面呈现、且不改变含义、层级、操作、状态、可访问性和验收时，按项目现有入口直接执行，不再因为「连续微调」自动升级治理等级。
- 交付与复盘只记录真实发生的事实；未完成的整改、待验证或失败的结论可以如实保留，材料按既有政策保留时也不需要编造新的批准人。

### 修复问题

- 修复把「决定整改」当成「整改已完成」的判定；只有存在真实改动、并完成对原问题和受影响行为的验证，才允许声明已验证解决。
- 修复把「保留材料」报告成「已按要求清理」的表述，以及只有一次重复失败就自动升级治理等级或追加规则的倾向。
- 修复客户端渲染副作用、事务归属、外部结果未知和恢复自身失败等场景缺少明确约束的问题；超时或取消不再被当作「外部动作没有发生」的证明。
- 修复新项目入口指向实际并未生成的文件，以及把安装过的 Skill 列表当成项目工程基线的问题。

## [2.7.1] - 2026-09-12
